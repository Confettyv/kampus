# Как работаем

## Ветки

- `main` — всегда рабочая версия. Прямых пушей нет, только через pull request.
- Одна задача — одна ветка от свежего `main`:
  `<тип>/<номер задачи>-<коротко>` — `feat/12-budget-today`, `fix/31-split-rounding`, `docs/4-api-contract`.
- Типы: `feat` — новая возможность, `fix` — исправление, `docs` — документы, `chore` — настройки,
  сборка, зависимости, `test` — только тесты.
- Ветка живёт не дольше недели. Большая задача делится на несколько PR.

## Коммиты

`<тип>: что сделано` по-русски, в настоящем времени: `feat: лимит на сегодня в ответе /budget/today`.
Один коммит — одно законченное изменение. Секреты (`.env`, ключи, пароли) в репозиторий не попадают.

## Pull request

1. Перед PR: `git fetch && git rebase origin/main`, локально проходят линт и тесты.
2. В описании — номер задачи (`Closes #12`), что сделано и как проверить. Для экранов — скриншот
   на 390 px и 1280 px.
3. Слияние — после одобрения ревьюера и зелёного CI. Ревьюер по умолчанию — Алим; его PR смотрит
   дублёр зоны: Никита ↔ Денис, Цецен ↔ Алим.
4. Слияние через «Squash and merge», ветка удаляется.

## Доска задач

Колонки: **Бэклог → На неделю → В работе → Ревью → Готово**.

- Задача — issue с меткой зоны (`зона: фронтенд`, `бэкенд`, `дизайн`, `devops`, `qa`) и вехой недели
  («Неделя 3 · 12–18.10»).
- Взял задачу — назначь себя и перенеси в «В работе». Открыл PR — «Ревью». Слили — «Готово» само.
- Созвон раз в неделю: что закрыто, что переносим, что мешает.

## Контракт API

Источник правды — [`docs/openapi.yaml`](docs/openapi.yaml). Меняется через PR, ревьюят Никита и Алим.
Фронтенд пишет по контракту на моках и не ждёт готовности бэкенда.
